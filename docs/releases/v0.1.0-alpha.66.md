# MagicHandy v0.1.0-alpha.66

## Changelog

- Recover automatically when the default local port is busy or denied by Windows. Launchers open the actual available address, while explicit fixed ports and hosted deployments remain strict. HNS is never reset automatically.
- Reopen a verified existing instance for the same app data directory instead of starting another backend. Language changes, voice installation and source updates also find the recovered address.
- Include the current startup, last failure and last automatic recovery in the standard diagnostic report, so port failures remain available after the app opens successfully.
- Keep cloud authentication status responsive while sign-in, refresh or remote revocation is waiting. Local sign-out takes effect before revocation completes, and late results cannot restore a session that was switched or signed out.
- Encrypt saved cloud credentials for the current Windows user, migrating existing credentials on first use. Older app versions cannot read the migrated store; moving data to another Windows account or computer may require signing in again.
- Add confirmed recovery for unreadable cloud credentials. Provider and model settings are retained, but saved sign-ins and API keys must be entered again. Remote grants must be revoked with their provider if needed.
- Build with Go 1.26.10 to fix GO-2026-6809 in certificate verification. Alpha.65 was blocked by its final binary scan and was never published; its source tag is retained.
- Existing device limits remain: Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path. Loaded COYOTE output and real vibrator behavior remain unverified, and a native Bluetooth worker crash may require reconnecting both devices.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.66`.
