# MagicHandy v0.1.0-alpha.74

## Changelog

- Fix Intiface vibrator startup alongside The Handy, silent output after reconnect, and conflicting Layered edits. Show each motor's commanded level and whether vibration is armed.
- Add independent steady, wave and pulse vibration for Advanced models in Layered and Creative v2. Vibrator changes preserve the Handy pattern and stay within the user's intensity and limits. A new manual motion request can resume after Stop; old replies and autonomous work cannot.
- Add Simple, Intermediate and Advanced model capabilities. Setup selects Intermediate for Gemma 12B and Simple for E4B. Advanced local models can use independent vibration and automatic timing when their inference hardware supports the larger context.
- Improve E4B and Intermediate motion guidance, constraint handling and Autopilot continuity. Intermediate's Extra planning switch in Chat > Autopilot trades a measured 0.4–0.7 seconds per decision for better constraint handling; it starts enabled and can be turned off.
- Reorganize model settings into Model roles and Models, with capability and context controls for each model. Keep motion settings on Chat and reply length under Prompts & memory.
- Update the optional managed llama.cpp CPU and CUDA runtime to b11533. Existing managed installs can update from settings; model files are retained.
- Real vibrator behavior, physical multi-Handy synchronization and loaded COYOTE output remain unverified. Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.74`.
