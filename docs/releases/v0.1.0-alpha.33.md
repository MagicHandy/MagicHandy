# MagicHandy v0.1.0-alpha.33

## Changelog

- Position-aware Cloud startup now recovers a bounded endpoint discrepancy
  measured on an Original Handy instead of flashing **Starting**, issuing a
  fail-safe Stop, and returning to idle before motion can begin.
- A stopped position up to 10% beyond the full travel inferred from the device's
  stroke response enters the existing engine-owned, speed-bounded acquisition
  lead-in. The raw distance is retained for timing, and main playback still
  requires a fresh stationary reading within the unchanged strict 1% arrival
  tolerance.
- Geometry outside that recovery envelope remains rejected before any Play
  command. Autopilot and Chat keepalive now end the exact failed mode generation
  instead of retrying unchanged unsafe geometry indefinitely; ordinary model
  and transport failures retain their existing retry backoff.
- The terminal teardown is generation-bound, so a delayed failure from an old
  run cannot stop a newer user-started Autopilot session.

## Diagnosis And Evaluation

Read-only inspection of the running user-installed alpha.32 instance separated
the planner from the startup failure. Its 97-row `motion_trace.v3` export had no
dropped rows and contained 15 valid Creative targets, 15 startup Stops, 15
slider/stroke reads, 15 `start_positioning_failed` events, and 15 failed starts.
Four additional decisions waited for the model. Slider speed was zero, and the
same failure recurred roughly every 5–15 seconds as model latency combined with
the three-second recovery backoff:

```text
motion startup absolute position was outside calibrated full travel
(position 111.33 maps to 108.7% of travel; device reported slide
0.0-100.0% as 5.00-102.83)
```

The LLM and Autopilot were therefore producing startable motion; the shared
engine correctly failed stopped, but its 3% initial calibration-excursion
allowance rejected this real endpoint report and the mode manager incorrectly
treated the unchanged safety state as transient. The fix remains inside the one
shared engine and mode lifecycle. It does not add a prompt exception, a private
Autopilot motion path, transport-owned timing, or a device-specific raw payload.

The exact 111.33/5.00–102.83 geometry is now a deterministic regression that
must complete one acquisition Play and one main Play. Separate boundary tests
accept 9.99% and reject 10.01% excursions on both ends. Gross invalid geometry
still produces no Play, and mode tests cover terminal circuit opening,
stale-generation protection, transient retry preservation, trace reasons, and
goroutine/Stop lifecycle.

A fresh isolated alpha.33 review app used a new data directory, fake transport,
and no connection key. The mandatory readiness script completed a real
generation on the available local llama.cpp model,
`n0404n0404-gemma-4-12b-it-heretic-b9a462-239ec3629639`. A text-only request
through MagicHandy's actual chat path then replied, “The MagicHandy chat path is
confirmed to be working,” in one 544 ms provider call with no repair, semantic
fallback, motion, or TTS. The visible Chat handoff has LLM motion Off, Autopilot
Off, and Motion Unavailable. Fake transport remained idle with zero commands;
the trace remained empty.

Full Go tests, vet, zero-issue lint, the pure-Go build, frontend localization,
typecheck/build and 408 tests, and the PowerShell 5.1 installer/release-policy
suite pass locally. Local Windows race remains unavailable because no C compiler
is installed; the mandatory Ubuntu CI race gate is authoritative for
publication.

The local Go 1.26.4 candidate is 24,116,224 bytes plain and 17,374,720 bytes
release-style stripped. The production frontend is byte-identical to alpha.32:
1,696,070 raw / 803,096 level-9 gzip bytes overall, 1,251,834 / 365,699 for
HTML/CSS/JS, and 810,664 / 214,069 for the English startup path.

No post-change physical motion was commanded. The user-installed alpha.32
process, controller lease, app data, device connection, and managed model were
not stopped or modified. A capped post-update device confirmation remains open.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
programs, and optional module state. This release corresponds exactly to source
tag `v0.1.0-alpha.33`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
