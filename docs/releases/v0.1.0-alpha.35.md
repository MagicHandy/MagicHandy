# MagicHandy v0.1.0-alpha.35

## Changelog

- Creative motion no longer retains whole-percent stationary edges around
  generated retarget reversals. Transition windows now receive the same bounded
  wire-quantization cleanup as steady generated motion.
- New append frames remove replaceable leading points that repeat the already-
  sent wire endpoint. Mandatory transition boundaries remain explicit, and the
  fitted tail remains protected so cleanup cannot shorten buffered coverage.
- The semantic Creative curve, 750 ms C2 transition, acceleration and jerk
  limits, shared motion engine, transport interface, and Emergency Stop path are
  unchanged.

## Diagnosis And Evaluation

The user reported that alpha.34 motion stopped at direction changes and
shuddered instead of flowing. Read-only inspection of the installed alpha.34
Cloud trace found six Creative Wander retargets at speeds 32 and 38. Every
retarget used the bounded bridge, and its emitted frame retained exact rounded
positions for 36-80 ms around a reversal. Cloud sends whole-percent positions,
so those repeated points became real stationary wire edges even though the
underlying smootherstep transition remained continuous and introduced no extra
semantic reversal.

The sampler had intentionally removed redundant rounded points from ordinary
generated frames but skipped that cleanup whenever a transition overlapped the
fit window. It also simplified each new append without comparing its first
point to the immutable endpoint already sent in the preceding append. The fix
applies cleanup to generated transition windows and performs that cross-append
comparison without removing mandatory transition boundaries. Protecting the
fitted final point keeps an all-one-wire-step transition buffered through its
required tail.

Deterministic regressions replay the reported Wander center 50, span 95, floor
40, phrase seed `2988185510`, variation 68, and 38-to-32 speed handoff. They
assert that steady append boundaries and the transition frame contain no
replaceable stationary wire edge, that both transition endpoints survive, and
that the final wire path remains within the fitter's position-at-time error
bound. An all-stationary transition must also retain buffer coverage. The
regressions passed 100 consecutive repetitions.

A user-driven current-source Cloud run then exercised Creative Wander at speed
65, span 80, floor 20, variation 40. Its active stream emitted 195 points over
10.395 seconds with strictly increasing timestamps, zero rounded duplicate
edges, and zero rounded stationary duration. Ten of 11 point appends succeeded
at 328-379 ms latency (343.1 ms average); one append returned a 15 ms network
error. User Stop completed successfully in 328 ms. The trace was exported
outside the repository. No subjective result was provided, so matched physical
feel remains an open acceptance item.

A separate fresh review app used an isolated data directory, fake transport,
and no device connection key. The mandatory readiness script completed a real
generation on the available llama.cpp model. A one-call text-only request
through MagicHandy's chat path replied, "The alpha.35 review chat path is
confirmed to be working correctly," with no motion, repair, or semantic
fallback.

Full Go tests, vet, zero-issue pinned lint, the pure-Go build, frontend
localization, typecheck/build and 408 tests pass locally. The motion regressions
also passed 100 consecutive repetitions. Local Windows race remains unavailable
because no C compiler is installed; the mandatory Ubuntu CI race gate is
authoritative for publication.

The local Go 1.26.4 candidate is 24,157,696 bytes plain and 17,404,928 bytes
release-style stripped. The production frontend is unchanged from alpha.34.

No hardware command was initiated by the release agent. The user-installed
alpha.34 process, app data, controller lease, and managed model were not stopped
or replaced. The user-driven current-source run used the existing shared Cloud
transport and ended with a successful user Stop.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
programs, and optional module state. This release corresponds exactly to source
tag `v0.1.0-alpha.35`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
