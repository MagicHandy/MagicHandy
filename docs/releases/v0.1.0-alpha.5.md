# MagicHandy v0.1.0-alpha.5

This corrective Windows alpha makes managed Python installation resilient to
redirected or policy-restricted Windows profiles. It includes all dependency,
source-retry, setup-layout, and verified llama.cpp fixes from alpha.4.

> **Superseded by alpha.6:** alpha.5 could recover the patch-specific Python,
> but `uv venv` recorded the rejected minor-version junction in its launcher.
> Use alpha.6 on affected Windows profiles.

## Install

Download `MagicHandy-0.1.0-alpha.5-windows-amd64-setup.exe`. Setup defaults to
`C:\Program Files\MagicHandy`, allows another destination, and offers an
optional desktop shortcut. Optional models and workers install only after an
explicit choice in guided setup.

The installer is currently **unsigned**. Windows may display an unknown
publisher or SmartScreen warning. Verify the download against
`MagicHandy-0.1.0-alpha.5-windows-amd64-SHA256SUMS.txt` before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.5-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.5-windows-amd64-SHA256SUMS.txt
```

The portable ZIP contains the same core payload without Windows shortcuts or
Add/Remove Programs integration.

## Managed Python Recovery

- Managed Python, uv's package cache, and uv credential lock files now live
  inside the selected voice provider below MagicHandy's app-data directory.
- Setup asks uv not to create user-PATH executable links or a global Python
  registry entry.
- uv always attempts an internal minor-version junction after extracting its
  patch-specific Python. If Windows rejects only that junction with an
  untrusted-mount policy, setup validates and uses the real patch-specific
  `python.exe` instead of discarding the completed install.
- Missing, incomplete, wrong-version, or non-runnable Python files remain fatal.
- Virtual-environment creation receives the exact validated interpreter and
  cannot trigger another implicit Python download.
- A compatible existing environment is still reused; an interrupted partial
  environment is replaced on retry.
- Faster Qwen verifies that `nvidia-smi.exe` can enumerate a GPU before Python,
  PyTorch, and model downloads, then retains the deeper PyTorch CUDA runtime
  check before model download.

The executable probing, app-owned dependency constraints, Chatterbox
ONNX/protobuf repair, provider imports, Hugging Face check, and CUDA validation
from alpha.4 remain in place.

## Upgrade And Uninstall

Install this build over an earlier alpha to retain settings and managed
components. Rerun the selected voice installation from guided setup after
updating; completed source and model downloads remain reusable.

Interactive uninstall asks whether to remove app-owned data from
`%APPDATA%\MagicHandy`; choose **Yes** for a clean reinstall. Silent uninstall
purges that directory unless `/KEEPUSERDATA` is supplied. New managed Python
runtimes and uv caches are inside that boundary. External Ollama models, media
and funscript folders, source checkouts, and custom data directories are never
removed.

## Known Alpha Limits

- Windows binaries are unsigned.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled;
  selected managed components can require several GiB of downloads.
- The in-app update checker follows stable GitHub releases. It does not announce
  alpha, beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change. Database migrations remain
  forward-only, so export irreplaceable personas, chats, and patterns before
  testing.
