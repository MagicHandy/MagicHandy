# MagicHandy v0.1.0-alpha.62

## Changelog

- Devices has a compact live panel and dedicated settings pages, with immediate saves, clearer status and a small + shortcut for adding another device.
- The Handy can connect through Native Bluetooth on Windows and Linux. Windows reconnect handling now releases and reacquires native device sessions more reliably.
- COYOTE 3.0 support includes discovery hints, remembered connections, channel ceilings and shared-session playback. Testing used disconnected output leads; loaded electrical behavior remains unverified.
- Linked sessions can include The Handy, COYOTE and an Intiface vibrator. Choose whether a failed device stops the whole session or leaves healthy devices playing. Vibrator support has simulation coverage only.
- Intiface playback on the Handy uses fewer optional updates while preserving fast reversals. Unloaded full-sweep, varying-pace and Creative v2 comparisons were smoother and natural; it is not identical to Cloud.
- Intiface Central 3.2.2 can report Stop without delivering a hardware Stop to The Handy. This upstream defect remains open; use Native Bluetooth or Handy Cloud for the device Stop path. A notice appears in Intiface settings.
- Local and hosted motion instructions handle full travel, pace edits, tip anchoring and Autopilot hold/release more consistently. Creative v2 also avoids floating-point endpoint rejection. Local context limits stay unchanged.
- Manual connection tests use supported patterns and honor saved speed limits. Installer startup failures include useful diagnostics, and Go network/crypto dependencies are updated.
- After a native Bluetooth worker crash, recovery may require Stop, disconnecting both devices and reconnecting. Seamless recovery while a companion keeps playing remains unverified.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped.
