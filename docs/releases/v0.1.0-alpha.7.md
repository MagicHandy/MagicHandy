# MagicHandy v0.1.0-alpha.7

This corrective release replaces the withdrawn alpha.6 distribution with a
portable-only Windows package and a fail-closed public artifact policy. It
contains the same managed-Python, llama.cpp, Parakeet, and voice recovery work,
plus the release-pipeline safeguards described below.

## Install

Download these two files:

- `MagicHandy-0.1.0-alpha.7-windows-amd64-portable.zip`
- `MagicHandy-0.1.0-alpha.7-windows-amd64-SHA256SUMS.txt`

Verify the ZIP before extracting it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.7-windows-amd64-portable.zip -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.7-windows-amd64-SHA256SUMS.txt
```

Extract the ZIP to a user-owned folder and run
`MagicHandy\magichandy.exe`. Guided setup opens in the browser. The core needs
no Go, Node, Python, CMake, Visual Studio, or CUDA Toolkit. Optional models and
workers install only after an explicit guided-setup action.

There is deliberately no public setup EXE in this release. The portable
executables remain unsigned while a trusted signing identity is provisioned.
If Defender or SmartScreen classifies the download as unsafe, do not bypass the
warning; retain the checksum and report the detection.

## Distribution Safety Correction

- The unsigned alpha.6 setup executable was withdrawn after Defender classified
  it as `Behavior:Win32/DefenseEvasion.A!ml` during launch.
- Public artifacts now come from a dedicated `artifacts/release` directory that
  contains exactly the portable ZIP and its one-entry checksum file.
- The release verifier rejects a setup executable in the portable-public
  artifact set.
- The unsigned Inno Setup package is still built and exercised on disposable
  Windows runners so custom/default paths, shortcuts, Add/Remove Programs,
  over-install, data retention, purge, and clean reinstall remain covered.
- That setup package is labeled `unsigned-ci`, retained for seven days as
  workflow evidence, and never attached to the GitHub Release.
- A future public setup package must have valid, timestamped Authenticode on the
  installer and every shipped executable from the explicitly pinned release
  signer. Self-signed certificates do not pass the release gate.

See [ADR 0014](../decisions/0014-public-windows-signing-gate.md) for the full
decision and [Windows Release Packaging](../windows-release-packaging.md) for
the verification commands.

## Upgrade And Data

Exit any existing MagicHandy process before starting the portable alpha.7
executable. By default it continues to use `%APPDATA%\MagicHandy`, so existing
settings and database migrations remain available. Do not manually overwrite a
Program Files installation with the portable files; keep the portable folder
separate until a signed setup upgrade is available.

Export irreplaceable personas, chats, and patterns before testing prereleases.
Database migrations remain forward-only.

## Known Alpha Limits

- The portable Windows executables are unsigned; public setup integration is
  temporarily unavailable.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled;
  selected managed components can require several GiB of downloads.
- The in-app update checker follows stable GitHub releases. It does not announce
  alpha, beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change.
