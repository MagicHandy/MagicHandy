# MagicHandy v0.1.0-alpha.71

## Changelog

- Add **Edge** above Stop to switch live motion to a gentle hold without waiting for AI. **Return** restores the previous motion; pressing Edge again keeps holding and cancels an automatic return.
- When Autopilot is active, its model can choose the hold duration and a bounded return pace. Failed or unsupported planning leaves a manual hold. Stop, pause, newer requests and changed settings cancel an outstanding automatic return.
- Improve Layered transitions when changing stroke regions or counted patterns, reducing unintended extra turns while preserving existing speed and range limits.
- Explain interrupted chat requests in plain language, including model timeouts, changed settings, lost control and expired sign-in. Technical details remain in Diagnostics.
- Keep the Edge control compact on desktop and mobile, showing status only when relevant. Video and timed-program playback do not support Edge.
- Physical comparison of the new transitions and Edge remains pending. Queued device motion can briefly continue after Edge; use Stop when motion must end. Decisions API planning currently leaves Edge in manual holding.
- Existing device limits remain: Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path. Loaded COYOTE output and real vibrator behavior remain unverified, and a native Bluetooth worker crash may require reconnecting both devices.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.71`.
