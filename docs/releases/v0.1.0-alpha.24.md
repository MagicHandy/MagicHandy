# MagicHandy v0.1.0-alpha.24

## Changelog

- Recalibrated the shared 1–100 motion-speed control against documented Handy
  travel and normal operating-speed ranges. On an Original Handy, 73% now
  requests about 299.6 mm/s instead of the former 144.5 mm/s equivalent.
- Added backend-authoritative Original, Handy 2 Standard, and Handy 2 Pro
  calibration profiles. The Connection menu presents them as three merged
  buttons with the selected travel and normal speed shown underneath.
- Renamed the user-facing Dynamic LLM mode to **Creative** while retaining the
  compatible `dynamic` settings/API identifier.
- Reworked Creative motion into a deterministic long-form phrase with bounded
  spatial drift, timing breathing, direction asymmetry, and an adaptive loop
  duration. Fractional curve sampling removes authored-millisecond plateaus.
- Separated quiet catalog-quality limits from the runtime rendered-curve
  envelope. Runtime acceleration is evaluated exactly on the final Hermite
  curve after focus, timing, and reversal-guide scaling.
- Replaced ordered Chat lists with labeled native set-point sliders and
  categorical lists with merged radio controls. Slider marks now align with the
  real thumb-center travel at every named stop.
- Polished the Chat control rail: compact session-tracking help, consistent
  Advanced spacing, stable symmetric scrollbar gutters, centered controls,
  narrower side padding, fixed-height LLM motion choices, a persistent
  full-width Motion status footer, and tint-only selected segments without
  tab-like underlines.

All motion still travels through the shared engine and transport interface;
profiles change semantic timing rather than constructing device payloads in the
browser or transport. Missing legacy profile settings default to Original
Handy, and no database schema migration is introduced.

## Known Limitations

- The reviewed manufacturer material publishes travel and normal speed, but no
  per-model acceleration envelope. All profiles therefore retain MagicHandy's
  shared software runtime envelope; motor RPM is not treated as acceleration
  evidence.
- Handy 2 Pro's optional 800 mm/s overclock is not exposed.
- Non-Handy Intiface actuators do not yet have a verified physical calibration
  profile.
- Automated schema, safety, frontend, and rendered-layout checks pass, but a
  matched post-change real-device A/B run with latency and `motion_trace.v3`
  evidence remains open.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
and optional module state. This release corresponds exactly to source tag
`v0.1.0-alpha.24`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
