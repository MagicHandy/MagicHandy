# MagicHandy v0.1.0-alpha.2

This corrective Windows alpha replaces the managed llama.cpp source-build
path shipped in `v0.1.0-alpha.1`. Fresh CUDA setup no longer depends on Visual
Studio CUDA build customizations, CMake, MSYS2, or the CUDA Toolkit.

## Install

Download `MagicHandy-0.1.0-alpha.2-windows-amd64-setup.exe`. Setup defaults to
`C:\Program Files\MagicHandy`, allows another destination, and offers an
optional desktop shortcut. The embedded setup page configures optional models
and workers only after an explicit choice.

The installer is currently **unsigned**. Windows may display an unknown
publisher or SmartScreen warning. Verify the download against
`MagicHandy-0.1.0-alpha.2-windows-amd64-SHA256SUMS.txt` before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.2-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.2-windows-amd64-SHA256SUMS.txt
```

The portable ZIP contains the same core payload without Windows shortcuts or
Add/Remove Programs integration.

## Managed llama.cpp Fix

- CPU installs the official pinned `b9966` Windows x64 archive, approximately
  18 MiB compressed.
- CUDA installs the official pinned CUDA 12.4 runner and runtime archives,
  approximately 628 MiB compressed and 1.1 GiB installed. It requires a
  compatible NVIDIA driver and GPU, but no compiler or CUDA Toolkit.
- Downloads resume after interruption, verify fixed sizes and SHA-256 digests,
  reject unsafe archive paths, and activate only after the exact `c749cb0`
  runner passes its version probe. CUDA also must detect a CUDA device.
- The upstream MIT license and archive provenance are stored with the managed
  runtime. Valid runtimes previously built from source remain usable.

## Upgrade And Uninstall

Install this build over `v0.1.0-alpha.1` to retain settings and managed
components. Interactive uninstall asks whether to remove app-owned data from
`%APPDATA%\MagicHandy`; choose **Yes** for a clean reinstall. Silent uninstall
purges that directory unless `/KEEPUSERDATA` is supplied. External Ollama
models, media and funscript folders, source checkouts, and custom data
directories are never removed.

## Known Alpha Limits

- Windows binaries are unsigned.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled;
  selected managed components can require several GiB of downloads.
- The in-app update checker follows stable GitHub releases. It does not announce
  alpha, beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change. Database migrations remain
  forward-only, so export irreplaceable personas, chats, and patterns before
  testing.
