# MagicHandy v0.1.0-alpha.67

## Changelog

- Fix sign-in when Edge or another password manager fills credentials without triggering input events. Filled values survive page updates and are submitted correctly.
- Open the main app and remote interface from external links without the “browser requests must use an allowed MagicHandy origin” error. Approved addresses, account permissions, and protections on API requests and settings changes remain enforced.
- Document external DNS-01 certificates and separate HTTPS ports for public deployments where port 443 is already in use, including conflicts with a running LAN listener during setup.
- Existing device limits remain: Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path. Loaded COYOTE output and real vibrator behavior remain unverified, and a native Bluetooth worker crash may require reconnecting both devices.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.67`.
