# MagicHandy v0.1.0-alpha.36

## Changelog

- Creative speed now represents calibrated mean travel through the selected
  Handy model's normal physical envelope. A requested percentage is no longer
  treated as though the instantaneous peak of an eased curve were the user's
  felt pace.
- Creative timing is solved per interval against the shared device-velocity,
  acceleration, jerk, reversal-spacing, and curve-geometry limits. Authored
  rhythm is retained until a real limit saturates; the motion status then shows
  the effective percentage beside the request and names the active limiter.
- C2 reversals remain rounded on short strokes. Longer legs progressively gain
  a cruise-like velocity body instead of spending the entire stroke in one
  nearly linear acceleration/deceleration shape. Stroke geometry—not selected
  time—chooses the curve, so slowing motion cannot make a turn more aggressive.
- Diagnostics can export the last stopped motion trace after the run or an app
  restart. The retained archive is redacted, capped at 128 rows and 1 MiB, and
  includes requested/effective pace evidence without making trace persistence
  part of Stop success.
- Autopilot no longer accepts continuity as a valid first motion decision when
  no target exists. The existing one-shot semantic repair asks the model for an
  authored first target; holds remain valid during a live phrase and while a
  previously owned phrase is recovering.
- Review and test processes may use `-simulate-motion` to route the complete
  shared motion engine through `fake_handy` without changing saved device
  ownership or allowing Cloud, Bluetooth, or Intiface motion dispatch.
- Emergency Stop keeps its established full-width shape while using the shorter
  **Stop** label, a larger square glyph and label, and a darker reserved-red
  treatment.

## Diagnosis And Evaluation

Alpha.35 converted selected device speed into a nominal semantic rate, then
fit an eased curve whose physical peak and reversal requirements could consume
substantial time. The UI still displayed the requested value even when the
compiled curve delivered a much lower mean travel rate. That is why a high
requested percentage could feel unexpectedly slow, particularly on a long C2
stroke: the number described an input to timing rather than the resulting felt
clock.

Alpha.36 defines the requested clock in mean semantic travel per second after
the selected Original / Handy 2 Standard / Handy 2 Pro calibration. The
compiler begins with each authored interval's relative rhythm, derives its
exact physical floor from the shared curve and safety envelopes, and distributes
the requested total duration over intervals that still have room. If the
request exceeds the reachable clock, the engine publishes the honest effective
percentage and constraint codes instead of silently presenting the request as
achieved. The 1–100 setting remains a user scale; it does not widen stroke
bounds or bypass device limits.

Representative fidelity regressions cover short, medium, long, unequal, and
multi-section Creative geometry on all three Handy profiles. They require pace
tracking before explicit saturation, monotonic requested/effective behavior,
geometry-stable turn shape, C2 continuity, and a cruise-like long-stroke body.
The existing 7,500%/s² acceleration, 150,000%/s³ jerk, 100 ms reversal-spacing,
per-device peak velocity, one-engine/one-sampler path, and unconditional Stop
contract are unchanged.

The first review Autopilot reproduction accepted the start request but repeated
`start_waiting_for_model` every three seconds. The configured 3B Granite model
returned a valid continuity decision even though no target existed, and repeated
that answer after repair. The scheduler previously collapsed the reason into a
generic waiting message. Startup now treats that as a semantic validation error
and traces the underlying reason. The review app was moved to the available 8B
Granite model, which authored a valid first Creative target and continued across
multiple decision boundaries.

The final release review used a fresh database with no saved device credentials
and the explicit simulator path. The exact-source app reported `fake_handy` on
every engine result, crossed multiple Creative segment boundaries, and retained
zero Cloud commands. This simulator is an explicit process-only override and is
not a production transport selector. No physical-transport latency series or
complete real-device trace was captured for alpha.36, so subjective comparison
remains open.

The exact review app completed direct provider generation and a real text-only
MagicHandy chat request on Ollama without motion. Autopilot then generated over
the same configured 8B model while the credential-free simulator owned the
motion boundary.

Full Go tests, vet, zero-issue pinned lint, the pure-Go build, frontend
localization, typecheck/build and 410 component tests pass locally. The
PowerShell 5.1 installer/release-policy suite also passes locally; the pull-
request and tag Windows package workflows remain authoritative for the exact
installer lifecycle and artifact publication. Local Windows race remains
unavailable because no C compiler is installed; the mandatory Ubuntu CI race
gate is authoritative.

The local Go 1.26.4 candidate is 24,205,824 bytes plain and 17,445,888 bytes
release-style stripped. The complete embedded UI is 1,699,951 raw / 804,516
level-9 gzip bytes; HTML/CSS/JS is 1,255,715 / 367,119, and the English startup
path is 812,618 / 214,675.

Subjective real-device comparison of alpha.36's effective pace and long-stroke
flow remains open. The compiler and diagnostics demonstrate the intended clock
and shape, but they do not substitute for felt A/B validation on each Handy
model.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
programs, and optional module state. This release corresponds exactly to source
tag `v0.1.0-alpha.36`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
