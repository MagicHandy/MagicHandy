# MagicHandy v0.1.0-alpha.11

This corrective release restores update notifications between prerelease builds
and makes fresh Faster Qwen3-TTS installs independent of Hugging Face snapshot
links on Windows.

## Install

Download these files:

- `MagicHandy-0.1.0-alpha.11-windows-amd64-setup.exe`
- `MagicHandy-0.1.0-alpha.11-windows-amd64-SHA256SUMS.txt`

The portable ZIP remains available when Windows installer integration is not
wanted. Verify the setup hash before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.11-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.11-windows-amd64-SHA256SUMS.txt
```

Setup preserves `%APPDATA%\MagicHandy` during an over-install. Optional models
and voice runtimes download only after an explicit guided-setup action.

## Update Discovery

- Alpha, beta, and release-candidate builds now discover newer compatible
  prereleases as well as a later stable release. In particular, alpha.9 reports
  alpha.10 and alpha.10 reports alpha.11.
- Stable builds continue to ignore prereleases. Beta builds do not move back to
  alpha, and release candidates do not move back to beta or alpha.
- The backend selects the highest valid semantic version from bounded paginated
  GitHub Releases, regardless of API ordering, and ignores drafts, malformed
  tags, and mismatched prerelease metadata.
- Update discovery remains advisory. MagicHandy opens the canonical release page
  and never downloads or executes an installer in the background.

## Managed Voice Correction

- Faster Qwen downloads now materialize a normal app-owned model directory with
  resumable local metadata. Runtime verification no
  longer depends on cache snapshot links that may be unavailable on a clean
  standard Windows account.
- Model and generation configuration, vocabulary and merges, preprocessors,
  speech tokenizer configuration, and both weight sets (including every indexed
  shard) are checked before setup reports success. The materialized directory is
  bound to its repository and rejects linked paths so changing model IDs cannot
  reuse or mix files from the previous model. Refreshes remain incomplete until
  all files validate, preventing an interrupted mutable-revision update from
  exposing mixed files. Existing complete alpha.10 snapshot caches remain
  supported.
- Program Files-style argument coverage proves the materialized model path stays
  one native `hf download --local-dir` argument.

## Acceptance Evidence

- A current core built with alpha.9 version metadata queried the live public
  release list and returned alpha.10 as `available` with the canonical release
  URL.
- Focused release-selection tests cover unordered responses, drafts, malformed
  tags, metadata mismatches, stable isolation, and alpha/beta/RC progression.
- Go tests, vet, lint, the zero-CGo build, frontend typecheck/build and tests,
  and the PowerShell installer/recovery suite pass. The release workflow reruns
  the mandatory race, Defender, and Windows package lifecycle gates.

## Distribution Safety

Alpha.11 retains the native x64 Inno loader and non-solid `zip/9` packaging. It
remains unsigned. The tag workflow scans the exact public artifact directory
with Microsoft Defender, verifies checksums and PE architecture, and exercises
custom and Program Files install, over-install, retention, purge, uninstall,
and clean reinstall before release creation.

Microsoft's prior `Not malware` determination for case
`15c1e36d-fb35-4c5d-85de-83707169818a` covered the submitted alpha.6 hash, not
this new artifact. Do not bypass a new Defender or SmartScreen classification;
retain the checksum and report it so the release can be withdrawn and reviewed.

## Known Alpha Limits

- The Windows binaries have no Authenticode publisher identity yet.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled and may
  require several GiB after explicit selection.
- Update discovery does not silently download, verify, or run an installer.
- Pre-1.0 settings, APIs, and user flows may change.
