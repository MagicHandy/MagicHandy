# MagicHandy v0.1.0-alpha.63

## Changelog

- Hosted Autopilot has an optional Auto timing setting. The model can choose when to reconsider motion, from 8 seconds to 5 minutes, using Motion change rate as its guide. It is off by default and can increase provider usage.
- External Autopilot planners can prepare their next decision while the current stretch plays, reducing delays at the next change. Prepare decisions early is on by default; chat, settings changes and Stop discard the prepared decision. Discarded calls may still count toward provider usage. Local planning keeps its existing timing.
- The Autopilot countdown keeps running while a prepared decision waits and marks the next motion ready.
- The Intiface Stop limitation disclosed in alpha.62 remains: Intiface Central can acknowledge Stop without delivering it to The Handy. Use Native Bluetooth or Handy Cloud for the Handy's device Stop path.
- Existing device acceptance limits remain: loaded COYOTE output and real vibrator behavior are unverified, and recovery after a native Bluetooth worker crash may require disconnecting and reconnecting both devices. The timing evaluation used simulated sessions, without physical-feel or long-session provider-usage acceptance.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped.
