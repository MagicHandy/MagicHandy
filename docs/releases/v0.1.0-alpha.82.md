# MagicHandy v0.1.0-alpha.82

## Changelog

- Keep directional Layered field slowdowns near constrained reversals instead of stretching the whole 64-cycle loop. Preserve adjacent direction contrast and the existing motion limits. Counted phrases retain a common clock; symmetric fields are unchanged. A bounded common-clock fallback remains available if local fitting does not converge.
- Stop autonomous retries after a startup move fails its arrival check. A fresh explicit Start remains possible and must still pass normal startup verification.
- Add **Reset and recheck** in Chat Motion status and the global device panel. This controller-only action confirms Stop and reads fresh stationary position/calibration data while playback stays stopped. It does not move to a target, recalibrate the device or bypass the next arrival check. Stale actions, engine replacement and Emergency Stop cancel or invalidate the reset.
- Clarify recovery notices and cancellation messages for missed arrival, invalid readings, motion after Stop and unsafe travel geometry.
- The owner preferred the retained local fit in all four focused Original Handy Cloud cadence conditions at 78%/100% in both direction orientations. All ten runs passed startup arrival and Cloud confirmed stopped after every run. This short, single-device comparison did not reproduce or explain the earlier Cloud failures or positioning mismatch; broader live-retarget and device acceptance work remains open.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.82`.
