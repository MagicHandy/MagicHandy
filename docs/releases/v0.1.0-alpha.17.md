# MagicHandy v0.1.0-alpha.17

## Changelog

- Made Autopilot timing and variability more model-owned. The model can choose
  settled, normal, or restless motion from the current conversation, and
  buildup changes are applied only after the current response is admitted.
  Speech is published before any motion coupled to that response. Session
  buildup accepts any positive whole-minute duration, including one minute,
  and background status refreshes no longer reset an in-progress duration edit
  to 30 minutes.
- Removed a motion handoff that could briefly cancel velocity when the same
  looping pattern changed tempo. Compatible same-direction updates now preserve
  phase without crossfading against themselves; reversals and geometry changes
  keep their bounded transition.
- Improved managed llama.cpp cold-start handling. An app-owned runner can remain
  in its documented loading state without being treated as failed, and partial
  structured replies are recovered more carefully when generation is cut off.
- Completed the update/setup lifecycle fix. A browser tab left on `#/setup`
  now returns to Chat when a completed installation comes back after an update.
  Deliberate reconfiguration uses `#/setup/reconfigure`, and setup steps reset
  their scroll position when advancing.

## Install Or Update

Download the setup EXE and checksum file from this release. Verify the checksum,
then run setup over the existing installation to preserve `%APPDATA%\MagicHandy`,
including settings, chats, personas, models, and optional module state.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
