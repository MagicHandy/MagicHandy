# MagicHandy v0.1.0-alpha.10

This corrective release fixes managed llama.cpp cold-start readiness and makes
fresh managed voice installs verify the runtime that the app will actually use.

## Install

Download these files:

- `MagicHandy-0.1.0-alpha.10-windows-amd64-setup.exe`
- `MagicHandy-0.1.0-alpha.10-windows-amd64-SHA256SUMS.txt`

The portable ZIP remains available when Windows installer integration is not
wanted. Verify the setup hash before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.10-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.10-windows-amd64-SHA256SUMS.txt
```

Setup preserves `%APPDATA%\MagicHandy` during an over-install. Optional models
and voice runtimes download only after an explicit guided-setup action.

## Runtime Corrections

- Managed llama.cpp recognizes upstream's structured HTTP 503 `Loading model`
  response as a bounded cold-load state instead of reporting a failed health
  endpoint. The managed readiness budget is 90 seconds and the Model screen
  follows the transition to ready.
- The official packaged and former source-built runners remain pinned to
  llama.cpp `b9966` / commit `c749cb041`. A current provider test against the
  verified packaged CUDA runner completed a real Gemma response, and the full
  current-app chat stream returned a valid reply.
- Fresh managed TTS setup clears obsolete worker-path overrides and verifies
  the managed Python, upstream server, MagicHandy adapter, and model or voice
  files before reporting success.
- Faster Qwen's installer probe and worker use the same app-owned Numba cache.
  Managed Python servers now use process-tree containment so Stop terminates
  launcher descendants instead of leaving a hidden interpreter and occupied
  port behind.

## Acceptance Evidence

- The packaged llama.cpp CUDA runtime reached ready, then the current app's
  chat SSE path returned `PACKAGED LLAMA READY` in 867 ms with a 714 ms first
  token and no motion selection.
- Faster Qwen reached ready on CUDA, completed the app voice queue with a valid
  99,884-byte WAV, and left no Python process or port 8991 listener after Stop.
- Go tests, vet, lint, the zero-CGo build, frontend typecheck/build and 383
  frontend tests, and the installer recovery suite pass. The release workflow
  reruns the mandatory race and Windows package lifecycle gates.

## Distribution Safety

Alpha.10 retains the native x64 Inno loader and non-solid `zip/9` packaging. It
remains unsigned. The tag workflow scans the exact public artifact directory
with Microsoft Defender, verifies checksums and PE architecture, and exercises
custom and Program Files install, over-install, retention, purge, uninstall,
and clean reinstall before release creation.

Microsoft's prior `Not malware` determination for case
`15c1e36d-fb35-4c5d-85de-83707169818a` covered the submitted alpha.6 hash, not
this new artifact. Do not bypass a new Defender or SmartScreen classification;
retain the checksum and report it so the release can be withdrawn and reviewed.

## Known Alpha Limits

- The Windows binaries have no Authenticode publisher identity yet.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled and may
  require several GiB after explicit selection.
- The in-app update checker follows stable releases and does not announce alpha,
  beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change.
