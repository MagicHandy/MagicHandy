# MagicHandy v0.1.0-alpha.38

## Changelog

- Setup and Settings can now enable password-protected accounts. A protected
  first-run setup ends at the Login screen, so the administrator password is
  required before the newly protected app can be used—even over local HTTP.
- Password creation now accepts a minimum of eight Unicode characters, up to
  1,024 UTF-8 bytes. Setup and Settings show live, accessible feedback for the
  length requirement and whether both password entries match.
- The permanent account interface includes Login, profile editing, profile
  images, administrator account management, password changes, and session
  revocation. Account state remains backend-authoritative across reloads.
- The top bar now has a compact control-profile selector. `Self` is selected in
  a normal session, and linked accounts are represented separately from login
  identity and controller-lease ownership so future multi-session and remote
  control work can extend the model without conflating those concepts.
- The backend now provides Argon2id password verification, administrator/member
  roles, bounded session cookies, login throttling, bootstrap protection, and
  revocation. Reconfiguring access preserves a valid administrator session;
  completing protected first-run setup deliberately revokes its temporary
  bootstrap session and requires a fresh login.
- HTTPS can be enabled for one exact private or link-local LAN address, while
  loopback HTTP remains the default. Certificate and account failures are
  fail-closed; setup never passes an account password to Inno Setup or places it
  in installer arguments.

## Security And Scope

Passwords are stored only as per-account Argon2id hashes with random salts and
bounded parameters. Authentication admission is globally bounded to avoid
uncontrolled password-hash concurrency, and raw passwords are not persisted,
logged, exported, or placed in diagnostics. Browser sessions use HttpOnly,
SameSite=Strict cookies and use Secure cookies when served over HTTPS.

Authentication remains separate from control-profile selection, controller
ownership, motion state, and transport commands. Emergency Stop remains
available without authentication, as required by the device-safety contract.
This release does not add Internet exposure, port forwarding, certificate
automation, invitation links, delegated control grants, concurrent controller
leases, password recovery, multi-factor authentication, or per-user chat and
library isolation. Remote access should remain limited to a trusted private
network until those later layers are designed and reviewed.

## Validation

Full Go tests, vet, zero-issue pinned lint, the pure-Go build, frontend
localization, typecheck/build, and all 426 component tests pass locally. The
PowerShell 5.1 installer and release-policy suite also passes locally; pull-
request and tag CI remain authoritative for race coverage, Microsoft Defender
scanning, and the exact clean-runner Windows installer lifecycle.

An exact packaged-binary loopback smoke test created a protected administrator,
confirmed private state returned HTTP 401 before login, logged in successfully,
and confirmed the simulated transport received zero device commands. The exact
review app used an isolated database and a simulated transport, and its
configured Ollama model completed a real text generation.

The local Go 1.26.4 candidate is 25,180,672 bytes plain and 18,167,296 bytes
release-style stripped. The complete embedded UI is 1,777,902 raw / 824,834
level-9 gzip bytes; HTML/CSS/JS is 1,333,666 / 387,437, and the English startup
path is 855,507 / 224,270. No new native dependency, browser framework, or
duplicated UI tree was added.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including accounts, profiles, settings, chats, personas,
models, patterns, programs, and optional module state. This release corresponds
exactly to source tag `v0.1.0-alpha.38`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
