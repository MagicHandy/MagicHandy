# MagicHandy v0.1.0-alpha.6

This corrective Windows alpha completes managed-Python recovery on redirected
or policy-restricted profiles. It includes all setup, dependency, source-retry,
and verified runtime fixes from alpha.5.

## Install

Download `MagicHandy-0.1.0-alpha.6-windows-amd64-setup.exe`. Setup defaults to
`C:\Program Files\MagicHandy`, allows another destination, and offers an
optional desktop shortcut. Optional models and workers install only after an
explicit choice in guided setup.

The installer is currently **unsigned**. Windows may display an unknown
publisher or SmartScreen warning. Verify the download against
`MagicHandy-0.1.0-alpha.6-windows-amd64-SHA256SUMS.txt` before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.6-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.6-windows-amd64-SHA256SUMS.txt
```

The portable ZIP contains the same core payload without Windows shortcuts or
Add/Remove Programs integration.

## Managed Python Recovery

- uv installs app-owned patch-specific Python without PATH links or registry
  registration. Its cache and credential store also remain provider-owned.
- If Windows rejects uv's optional minor-version junction after extraction,
  setup validates and retains the real patch-specific interpreter.
- That interpreter now creates the private environment through CPython's
  `venv --without-pip`, producing standard Windows launchers and an exact
  patch-specific `pyvenv.cfg` home. uv installs dependencies into that verified
  environment afterward; a bundled pip is not required.
- A retry recognizes alpha.5's uv trampoline environment, removes that private
  environment even if it still starts locally, and rebuilds it without
  redownloading the managed Python.
- Missing or non-runnable patch-specific Python remains fatal. Unrelated uv
  failures are never treated as junction recovery.
- Checked native dependency commands preserve streamed diagnostics but use
  process exit status as the authority, preventing harmless stderr output from
  bypassing cleanup and recovery logic.
- Saved-module reuse now validates `pyvenv.cfg` plus both Python launchers. A
  full source install repairs a failed runtime check with the saved choices;
  ordinary core-only updates still avoid replaying optional downloads.

The verified llama.cpp archives, resumable and checksum-verified Parakeet
assets, atomic pinned-source checkout, dependency constraints, CUDA probe,
provider imports, Hugging Face verification, and model-download resume behavior
remain unchanged.

## Upgrade And Uninstall

Install this build over an earlier alpha to retain settings and managed
components. Rerun the selected voice installation from guided setup. Alpha.5's
private uv environment is replaced automatically; completed source and
model downloads remain reusable.

Interactive uninstall asks whether to remove app-owned data from
`%APPDATA%\MagicHandy`; choose **Yes** for a clean reinstall. Silent uninstall
purges that directory unless `/KEEPUSERDATA` is supplied. External Ollama
models, media and funscript folders, source checkouts, and custom data
directories are never removed.

## Known Alpha Limits

- Windows binaries are unsigned.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled;
  selected managed components can require several GiB of downloads.
- The in-app update checker follows stable GitHub releases. It does not announce
  alpha, beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change. Database migrations remain
  forward-only, so export irreplaceable personas, chats, and patterns before
  testing.
