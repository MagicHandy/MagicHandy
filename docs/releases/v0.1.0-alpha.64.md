# MagicHandy v0.1.0-alpha.64

## Changelog

- Fix Layered response failures with ChatGPT and other external models by making conflicting control, shape and layer choices mutually exclusive. Corrections also cover Autopilot and optional second opinions.
- Hosted Autopilot distinguishes one-time pace changes and temporary intervals from lasting preferences, allowing natural development to resume while preserving explicitly retained limits. Local model prompts remain unchanged.
- Fix named centered, base and tip motion choices failing when a narrowed travel band inherited a wider stroke setting.
- External connections now show their request context budget separately from conversation history. Choose a larger supported budget with shorter history to leave room for motion planning without sending a longer conversation. Existing saved settings and local context limits are preserved; larger histories may increase latency and provider usage.
- These planning improvements were evaluated with live ChatGPT responses and compiled motion, without new physical-device acceptance. Hosted planning remains experimental.
- Existing device limits remain: Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path. Loaded COYOTE output and real vibrator behavior remain unverified, and a native Bluetooth worker crash may require reconnecting both devices.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.64`.
