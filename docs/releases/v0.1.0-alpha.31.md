# MagicHandy v0.1.0-alpha.31

## Changelog

- Creative Autopilot now treats an enabled session as continuing authorization
  for bounded autonomous choices. Quiet chat no longer reads as an implicit
  request to hold, while explicit requests to keep motion unchanged still win.
- Motion change rate is expressed to the model as a whole-phrase continuity
  bias. At higher levels it favors meaningful contrast in the outer travel
  band, stroke-length envelope, texture, or multi-section structure instead of
  speed-only churn or tiny scalar nudges. It remains a preference rather than a
  forced-change deadline.
- Phrase freshness remains anchored to the last materially different compiled
  motion. Several smooth steps can therefore accumulate into a perceptible
  range change without requiring the abrupt jump that made earlier motion feel
  robotic.
- Autonomous spoken check-ins use recent lines as anti-repetition context. They
  avoid recycling sentence shape, physical action, image, or salient noun and
  prefer a genuinely new conversational beat without prescribing persona-
  specific prose.
- Managed llama.cpp starts at low process/thread priority. Frequent CUDA prompt
  prefill now yields to Emergency Stop, the app shell, and displayed backend-
  owned clocks instead of making the speech countdown appear to skip seconds.
  Backend deadlines remain authoritative.
- A model response containing exactly one `sections` item is losslessly
  promoted to the equivalent single Creative phrase. This removes a redundant
  repair inference without weakening strict rejection of conflicting or
  incomplete motion geometry.
- An explicit `span_profile:"steady"` now clears a running stroke-length
  envelope even when a local model copies the prior floor. A floor-only update
  with no explicit profile still selects ordinary organic wander.

## Diagnosis And Evaluation

Read-only inspection of the user-installed alpha.30 Hei session found two
separate regressions. The opening Creative phrase survived nine consecutive
model hold decisions for about two minutes at motion-change rate 8. Later
updates changed speed and inner values but stayed largely inside one spatial
character: centers 45–50%, widest spans 35–54%, effective lower bounds about
21–30%, effective upper bounds about 65–76%, and only the Wander profile.

The speech scheduler's backend deadlines were correct. Autonomous inference on
the managed CUDA llama.cpp process took about 2.0–2.3 seconds; the shorter motion
countdown was replaced by its `planned` state during that work, while the speech
countdown remained numeric and exposed the missed render opportunities. The
priority change addresses host scheduling pressure without inventing a second
frontend clock or changing elapsed-session accounting.

Transport-free evaluations used the active installed llama.cpp model,
`n0404n0404/gemma-4-12b-it-heretic-b9a462:latest` (provider ID
`n0404n0404-gemma-4-12b-it-heretic-b9a462-239ec3629639`):

- Repeated production-path, maximum-rate sessions produced materially different
  compiled range character by decisions 3–6 while preserving smooth cumulative
  movement. The harness does not prescribe which turn must change and creates
  no engine or transport.
- A long maximum-rate phrase still returned `action:none` when recent
  conversation explicitly requested unchanged motion.
- The Hei speech-novelty fixture includes all four repetitive lines observed in
  the installed session and produced a distinct line with varied opening and
  content.
- The complete nine-case interactive Dynamic matrix passed on first responses.
  Five repeated anchored-start cases that previously required a second repair
  inference passed first-response parsing after lone-section promotion. The
  terse correction follow-through cases also remained green.

The final isolated current-source review app used fake transport and no device
credential. Its readiness probe completed real text generation on the exact
model. A text-only MagicHandy chat then replied, “The system is functioning
correctly and ready for your commands.” in one 976 ms generation with no repair
indicators. Autopilot remained off, motion was unavailable, and transport
command count remained zero.

Full Go tests, vet, zero-issue lint, frontend localization/typecheck/build and
408 tests, the PowerShell 5.1 installer/release-policy suite, and plain/stripped
`CGO_ENABLED=0` builds pass locally. Local Windows race remains unavailable
because no C compiler is installed; the mandatory Ubuntu CI race gate is
authoritative for publication.

The local Go 1.26.4 candidate measures 24,137,728 bytes plain and 17,370,112
bytes release-style stripped. Production frontend bytes are unchanged from
alpha.30 because the frontend change is regression coverage only: 1,696,068 raw
/ 803,095 level-9 gzip bytes overall, 1,251,832 / 365,698 for HTML/CSS/JS, and
810,662 / 214,068 for the English startup path.

No post-change physical motion was commanded. Prompt, parser, compiler, and
clock evidence do not replace subjective hardware acceptance. A capped matched-
device comparison on each Handy profile, including continuity and Emergency
Stop, remains open.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
programs, and optional module state. This release corresponds exactly to source
tag `v0.1.0-alpha.31`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
