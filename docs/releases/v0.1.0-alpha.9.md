# MagicHandy v0.1.0-alpha.9

This corrective release fixes the managed Faster Qwen3-TTS installation path
on Windows. It also applies the same path-safe dependency invocation to
Chatterbox installs.

## Install

Download these files:

- `MagicHandy-0.1.0-alpha.9-windows-amd64-setup.exe`
- `MagicHandy-0.1.0-alpha.9-windows-amd64-SHA256SUMS.txt`

The portable ZIP remains available when Windows installer integration is not
wanted. Verify the setup hash before running it:

```powershell
(Get-FileHash .\MagicHandy-0.1.0-alpha.9-windows-amd64-setup.exe -Algorithm SHA256).Hash.ToLowerInvariant()
Get-Content .\MagicHandy-0.1.0-alpha.9-windows-amd64-SHA256SUMS.txt
```

Run setup over an existing packaged installation or choose a new destination.
Setup preserves `%APPDATA%\MagicHandy` during an over-install. Optional models
and voice runtimes download only after an explicit guided-setup action.

## Managed Voice Corrections

- `uv` no longer receives absolute local dependency paths rooted under
  `C:\Program Files`. The installer runs dependency operations from the
  app-owned module directory with relative Python, constraint, requirements,
  and editable-source paths.
- Python environment creation uses the same module-relative boundary, including
  the app-owned Python installation directory and virtual environment target.
- Runtime verification is a packaged `runtime-probe.py` file instead of a
  multiline `python -c` argument. Windows PowerShell 5.1 stripped embedded
  double quotes from the old argument and produced a misleading unclosed
  parenthesis syntax error after all packages had installed successfully.
- Interrupted retries retain the managed source, Python environment, package
  cache, and completed downloads when they pass integrity checks.
- Regression coverage exercises Program Files-style paths and verifies that
  runtime checks invoke the packaged script without dynamic command text.

## Distribution Safety

Alpha.9 keeps alpha.8's native x64 Inno loader and non-solid `zip/9` packaging.
It remains unsigned. ADR 0014 authorizes only alpha.8 and alpha.9 under the
version-bound `ReviewedUnsignedPublic` policy. The tag workflow scans the exact
alpha.9 public artifact directory with Microsoft Defender, verifies every
checksum and PE architecture, and exercises custom and Program Files install,
over-install, retention, purge, uninstall, and clean reinstall before release
creation.

Microsoft's prior `Not malware` determination for case
`15c1e36d-fb35-4c5d-85de-83707169818a` covered the submitted alpha.6 hash, not
this new artifact. Do not bypass a new Defender or SmartScreen classification;
retain the checksum and report it so the release can be withdrawn and reviewed.

## Known Alpha Limits

- The Windows binaries have no Authenticode publisher identity yet.
- Models, Python, llama.cpp, Parakeet, and TTS runtimes are not bundled and may
  require several GiB after explicit selection.
- The in-app update checker follows stable releases and does not announce alpha,
  beta, or release-candidate builds yet.
- Pre-1.0 settings, APIs, and user flows may change.
