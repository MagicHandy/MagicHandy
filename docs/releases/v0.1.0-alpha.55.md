# MagicHandy v0.1.0-alpha.55

## Changelog

- Creative v2 now requires a non-empty chat reply in its model-output schema and prompt, preventing schema-compliant empty replies that the app cannot accept.
- Rejected Creative v2 responses now identify the failed field: missing or null edits, too many edits, a blank reply, or an oversized reply. Edit counts and reply byte lengths appear where relevant.
- Invalid responses continue to leave motion unchanged and stay out of assistant history. Ordinary conversation still uses an empty edits array; no automatic retry or inferred motion is added.
- Repeated greetings pass on the local review models. The cause of the reported consistent greeting failure remains unconfirmed until the user's prompt, status and failed model output are available.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve its data; portable users replace the application files while the app is stopped.
