# MagicHandy v0.1.0-alpha.70

## Changelog

- Automatically ask external chat models to correct a rejected motion response once. Turn this off in model settings to use the **Repair response** button beside an eligible chat error instead. Corrections add one request; provider refusals and connection errors are not retried this way.
- Keep rejected attempts and correction outcomes in Diagnostics. External corrections cannot revive a request after Stop or replace a newer motion change.
- Let ChatGPT and other external models start motion from a fresh motion request while stopped, without requiring the word “start.” Questions, future-only instructions, Pause, LLM motion Off and script-owned playback retain their existing boundaries.
- Improve Layered guidance for joining counted strokes across separate regions, with clearer rejection feedback and preservation of requested counts and coverage.
- Give local Layered and Creative v2 chat one correction attempt for invalid structured responses when the configured context has room. Help local Pattern library replies match the playback state and avoid unnecessary retries in paused Creative chat, without adding requests to successful replies.
- Local models can still miss compound range or pace requests, and some terse start requests still need clearer wording. Physical validation of the new motion proposals remains pending; commanded endpoints do not confirm physical carriage reach.
- Existing device limits remain: Intiface Central may acknowledge Stop without delivering it to The Handy; use Native Bluetooth or Handy Cloud for its device Stop path. Loaded COYOTE output and real vibrator behavior remain unverified, and a native Bluetooth worker crash may require reconnecting both devices.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.70`.
