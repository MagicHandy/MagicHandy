# MagicHandy v0.1.0-alpha.80

## Changelog

- Improve effective pace near the top of The Handy's speed range while preserving sparse motion output and rounded direction changes. Original Handy Cloud comparisons found the full-range, short-stroke and counted compound patterns faster and still smooth. Narrow strokes and deliberate direction contrasts can still limit average pace.
- Add OpenRouter reasoning controls to Setup and Settings: Provider default, Off where supported, Enabled, and the model's advertised effort levels. Show the default effort, preserve Off across compatible model switches, and avoid false errors while model details load.
- Give reasoning-enabled OpenRouter requests consistent output room across chat, Autopilot, Edge, review and repair. A successful connection check no longer conceals a smaller chat budget. Reasoning can add latency and token use; explicit Off retains the usual smaller budgets.
- Clarify Advanced Layered stroke lengths and full-band requests. Keep chat, Autopilot, second-opinion evidence and repair feedback consistent, reducing contradictory geometry and field-name errors. Simple and Intermediate retain their compact contracts.
- Explain unsupported reasoning settings directly instead of reporting a provider outage. ChatGPT/OpenAI support and provider refusal handling remain intact.
- Physical acceptance of the new top-speed shaping is limited to the tested Original Handy Cloud patterns. Other devices/transports, simultaneous-device behavior and some transitions still need hands-on checks; earlier Cloud recovery-stop and Intiface Stop limitations remain open. Models can still misunderstand requests.
- Windows setup remains unsigned under the reviewed alpha policy. Install over the existing app to preserve data; portable users replace application files while the app is stopped. Source: `v0.1.0-alpha.80`.
