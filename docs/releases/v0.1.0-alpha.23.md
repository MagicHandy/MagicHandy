# MagicHandy v0.1.0-alpha.23

## Changelog

- Added a selectable **Dynamic** LLM motion mode to the Chat sidebar. In this
  mode the model chooses semantic speed, stroke window or anchor route, slow
  variation, and decision horizon without selecting a catalog pattern. Pattern
  Library remains the default mode, and both modes use the shared motion engine
  and transport path.
- Added continuous Dynamic retargeting with phase and velocity preservation,
  bounded geometry, trace visibility, and backend-authoritative motion status.
- Integrated Dynamic decisions with Autopilot. Initial autonomous geometry is
  supplied through the Dynamic decision contract; a model hold or provider
  failure now waits or preserves the current Dynamic target and cannot silently
  fall back to a catalog pattern.
- Reduced stable prompt churn for managed llama.cpp and clarified the current
  state action set. Direct embodied requests are handled as a general motion
  intent class instead of a phrase list, while the model retains ownership of
  whether to change or hold active motion.
- Kept user-facing reply wording consistent with the selected motion action so
  a hold or update is not described as a new start.
- Corrected spacing and height alignment between **Check now** and **View
  release** in Settings. The actions remain aligned on desktop and stack at
  equal width on narrow screens.

Dynamic prompt and Autopilot startup behavior were exercised against the
managed Gemma model without constructing a motion engine or transport. The
ordinary Go, race, lint, architecture, pure-Go, frontend, installer, Defender,
and release-artifact gates remain authoritative for this release. No database
schema migration is introduced.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
and optional module state. This release corresponds exactly to source tag
`v0.1.0-alpha.23`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
