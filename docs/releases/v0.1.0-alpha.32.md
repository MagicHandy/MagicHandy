# MagicHandy v0.1.0-alpha.32

## Changelog

- Editing the Settings-backed **MagicHandy (Default)** persona from the Personas
  page now opens **Settings > Prompts & memory** instead of the unrelated Model
  section.
- The target section owns the default prompt set, reply register, persona
  description, anatomy context, prompt editor, and long-term memories. Custom
  personas still open their existing persona editor; selecting a persona still
  changes only the active chat rather than global settings.
- The persona-page design and component regression now state the owning route
  explicitly so the incorrect Model deep link cannot be silently restored.

## Diagnosis And Evaluation

The defect reproduced in alpha.31 on the default persona card itself: its anchor
was hard-coded as `#/settings/model`, and the component test asserted that wrong
value. The Prompts & memory section already existed as `#/settings/prompts` and
already contained every Settings-backed default-persona control, so no routing,
settings, persona, or backend schema change was required.

A fresh isolated current-source app verified the complete rendered path:

1. `#/personas` loaded **MagicHandy (Default)** with href
   `#/settings/prompts`.
2. Clicking the card navigated to `#/settings/prompts`.
3. The visible section heading was **Prompts & memory**.
4. The default **Persona description** control was present.

The isolated app used a fresh data directory, fake transport, and no copied
device or API credential. Transport command count remained zero. Its real-model
readiness probe succeeded against the available local llama.cpp model,
`n0404n0404-gemma-4-12b-it-heretic-b9a462-239ec3629639`, and a text-only
MagicHandy chat replied, “The chat is working correctly.” Motion remained
unavailable and Autopilot remained off.

The focused persona-component suite passes 25/25. Full Go tests, vet, zero-issue
lint, frontend localization/typecheck/build and 408 tests, the PowerShell 5.1
installer/release-policy suite, and plain/stripped `CGO_ENABLED=0` builds pass
locally. Local Windows race remains unavailable because no C compiler is
installed; the mandatory Ubuntu CI race gate is authoritative for publication.

The local Go 1.26.4 candidate remains 24,137,728 bytes plain and 17,370,112
bytes release-style stripped. The corrected two-character route changes the
canonical browser measures by only 2 raw / 1 level-9 gzip byte: 1,696,070 /
803,096 overall, 1,251,834 / 365,699 for HTML/CSS/JS, and 810,664 / 214,069 for
the English startup path.

No physical motion was commanded. This update changes one browser navigation
target and does not alter motion, transport, model inference, or device safety
behavior.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
programs, and optional module state. This release corresponds exactly to source
tag `v0.1.0-alpha.32`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
