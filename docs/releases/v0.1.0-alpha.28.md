# MagicHandy v0.1.0-alpha.28

## Changelog

- Creative motion now uses monotone C2 quintic-Hermite curves. Position,
  velocity, and acceleration remain continuous at every knot and at the loop
  seam, replacing the remaining acceleration corner at true reversals.
- Exact acceleration and Creative-only perceptual jerk extrema feed the shared
  runtime fitter. Overly abrupt plans are lengthened through the existing motion
  engine rather than clipped or routed through a second motion path.
- Creative whole-percent output preserves both position-at-time and
  time-at-position while simplifying for the wire. Short eased strokes therefore
  retain their braking shape after 1% Cloud quantization instead of collapsing
  toward a linear ramp.
- The model may describe one long phrase as two to four complete semantic
  sections in a single response. Each section owns its route, stroke-length
  envelope, texture, and cycle count; the backend expands them into one
  loop-closed curve lasting at least 60 seconds at maximum-reference travel.
- Phrase replacements advance bounded deterministic novelty. Stroke lengths,
  grouped leg timing, and range trajectories vary without per-sample noise, raw
  model-authored points, or a private motion loop.
- Pace-only requests preserve the live phrase even when a model copies unrelated
  geometry. Failed position corrections must change reach, and running `start`
  responses normalize to `update` without expanding the system prompt with
  phrase-specific edge-case scripts.
- Chat's Autopilot timing control is now named **Motion change rate** and has
  eight numbered stops. Levels 1–7 retain their previous timing windows; the new
  level 8 uses a tighter 8–16 second decision window. The former fewer/more
  explanation has been removed.
- Review builds now require a working configured LLM and a real generation
  probe before handoff. LLM-related changes additionally require one text-only
  MagicHandy chat completion with no repair, fallback, or motion command.

## Evaluation

Automated motion coverage verifies C2 acceleration continuity at unequal knots
and the loop seam, monotonic no-overshoot behavior, exact acceleration and jerk
envelopes, all three Handy profiles, whole-percent inverse-timing preservation,
and at least six distinct reversal lengths with coefficient of variation above
0.15.

The focused local Ollama matrix passed evolving multi-section start, running
phrase replacement, pace-only preservation, and a failed tip correction in one
run without repair or semantic fallback. The release review app also completed
a separate text-only MagicHandy chat turn through the configured Ollama model
with `motion: null`. Neither check constructed or reached a physical transport.

No post-change device motion was commanded during release validation. A matched
real-device Creative-versus-Pattern-Library feel comparison, transport latency,
trace export, and physical Stop evidence remain open acceptance work.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
and optional module state. This release corresponds exactly to source tag
`v0.1.0-alpha.28`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
