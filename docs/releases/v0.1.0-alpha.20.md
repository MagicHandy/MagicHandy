# MagicHandy v0.1.0-alpha.20

## Changelog

- Made pattern shape and playback speed independent. Repeating patterns now
  target one shared semantic travel rate, so changing `speed_percent` produces
  a meaningful proportional pace change instead of being mostly overridden by
  the pattern's original timing.
- Preserved motion safety while retiming. Curve-specific acceleration and
  reversal limits still cap unsafe requests, including reversals at the loop
  boundary, focused-area compression or expansion, and soft anchoring.
- Reworked the model-facing pattern catalog around geometry and relative
  rhythm. Historical pace labels and persisted IDs no longer steer selection;
  existing IDs remain stable in the database and untouched default names
  migrate without overwriting user renames.
- Standardized Chat, Autopilot, the Pattern Library API, and the browser UI on
  `speed_percent`. Older `intensity` requests remain accepted and are normalized
  immediately for compatibility.

Installed Gemma/llama.cpp evaluation produced strict valid Chat output on 10 of
10 turns and valid full-catalog Autopilot decisions on 12 of 12 turns, using
nine speeds and six patterns. These checks did not enter the motion engine or
transport. No physical device motion was commanded during release validation,
so subjective low-speed and reversal feel remain open testing work.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, patterns,
and optional module state. This release corresponds exactly to source tag
`v0.1.0-alpha.20`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
