# MagicHandy v0.1.0-alpha.29

## Changelog

- Creative Autopilot now tells the LLM how long the effective motion phrase has
  remained the same, how many autonomous decisions have reconsidered it, and
  how many explicit holds occurred consecutively. Pace-only changes, decision-
  horizon changes, and backend novelty seeds do not reset phrase age.
- Motion change rate remains a preference rather than a deterministic timer.
  Higher levels tell the model that more frequent meaningful differences are
  welcome, but no elapsed threshold forces a change and a deliberate hold stays
  a valid first-class decision.
- The autonomous Creative contract now exposes the already supported stroke-
  length envelope and multi-section fields, plus the current decision horizon.
  Effective span validation gives one complete repair instruction when a model
  selects an inner floor that cannot fit inside the current outer span.
- Creative is now the default LLM motion mode for fresh installs and settings
  documents that predate the selector. Explicit saved Pattern Library and Off
  choices remain unchanged; a legacy chat-only capability still resolves Off.
- Six built-ins disabled in the installed alpha.28 profile are retired from the
  shipped catalog: Broad and Tight, Deep-Shallow Sequence, Flutter, High-Low
  Blocks, Lower Accents, and Three and One. The catalog now contains 81 entries,
  25 non-experimental and 56 experimental.
- Catalog reconciliation removes those IDs only when the stored row is a
  canonical built-in. User-authored rows, settings, programs, and imported
  content are not deleted.
- The review-readiness probe disables thinking mode for llama.cpp. A thinking-
  capable model can no longer spend the probe's small output budget entirely on
  hidden reasoning and appear unavailable despite producing valid app replies.

## Evaluation

Read-only inspection of the user-installed alpha.28 session showed that Motion
change rate level 8 was scheduling correctly: model decisions occurred roughly
every 12 seconds inside the configured 8–16 second range. The model then chose
six consecutive holds, preserving one effective phrase for about 92 seconds.
Session age and speed age were visible to the model, but semantic phrase age,
reconsideration count, hold streak, and current horizon were not. The terminal
`segment_failed` trace event occurred immediately after the user paused motion
and reported `motion is not running`; it was teardown noise, not an LLM,
transport, or device failure.

Transport-free probes used the session's active llama.cpp model,
`n0404n0404/gemma-4-12b-it-heretic-b9a462:latest`:

- Before the change, otherwise identical initial decisions held at both 12 and
  72 seconds, and later decisions repeated a narrow scalar recipe without span
  envelopes or sections.
- After the change, 3/3 short-age initial cases still held, demonstrating that
  no forced threshold was introduced. The otherwise identical 72-second,
  six-hold cases changed in 3/3 runs and used valid range envelopes.
- A 12-decision evolving session produced one hold, 11 semantic phrase changes,
  11 variable stroke-length envelopes, four distinct decision horizons, no
  repair, and no semantic fallback. The model did not choose sections, and the
  harness did not force it to do so.

The installed catalog snapshot contained 87 built-ins: 81 enabled and the six
retired entries disabled. It contained no disabled user-authored patterns. The
installed application and its database were not modified during diagnosis.

The isolated current-source review app used a fake transport and the same active
llama.cpp endpoint. The direct readiness probe returned visible text without a
controller. Default-Creative factual turns completed in one provider call with
an authoritative `action: none` and no dispatch; a separate temporary chat-only
probe completed with `motion: null`, no repair, and no semantic fallback, after
which the review setting was restored to Creative. The app controller was used
only to submit chat text; no physical transport was available or invoked.

Full Go tests, vet, zero-issue lint, frontend localization/typecheck/build and
405 tests, the Windows PowerShell 5.1 installer suite, the catalog designer, and
plain/stripped `CGO_ENABLED=0` builds pass locally. Local Windows race remains
unavailable because no C compiler is installed; the mandatory Ubuntu CI race
gate remains authoritative for publication.

The local Go 1.26.4 candidate measures 24,067,584 bytes plain and 17,321,472
bytes release-style stripped. The canonical browser output remains byte-
identical in size at 1,695,193 raw / 802,815 level-9 gzip bytes overall and
809,787 / 213,788 for the English startup path.

No post-change device motion was commanded. The installed Cloud trace's recent
commands were successful at roughly 300–350 ms latency, but that is diagnostic
context rather than matched post-change feel evidence. A capped Creative versus
Pattern Library physical comparison, including subjective continuity and
Emergency Stop, remains open.

## Install Or Update

Download the setup EXE and SHA-256 checksum file from this release. Verify the
checksum, then run setup over the existing installation to preserve
`%APPDATA%\MagicHandy`, including settings, chats, personas, models, remaining
patterns, programs, and optional module state. On first launch after the update,
the six retired canonical built-ins are removed from the local catalog. This
release corresponds exactly to source tag `v0.1.0-alpha.29`.

The Windows setup EXE remains unsigned, Defender-scanned, and lifecycle-tested.
Windows may still show an unknown-publisher reputation warning. Do not bypass a
malware detection; report the exact filename and checksum instead.
